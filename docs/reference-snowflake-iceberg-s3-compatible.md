# Snowflake Horizon Catalog：S3 互換ストレージと Iceberg

## 1. 対象と前提

S3 互換ストレージ上の Iceberg テーブルを外部エンジンへ公開する際のパスと認証を追う。 公式資料を組み合わせた説明用のモデルで、実機の配置や導入事例ではない。

## 2. 構成と役割

- **外部エンジン**：Iceberg REST API 対応エンジンが表へのアクセスを要求する。
- **カタログとアクセス判定**：表の登録情報と権限を確認し、エンジンへ提供する。
- **ストレージ位置の解決**：内部のストレージ種別からクライアントが解釈できるアクセス形式を決める。
- **アクセスの許可**：対応する環境では一時的なアクセス情報を使い、外部エンジンのアクセスを管理する。
- **Iceberg メタデータ**：外部エンジンが解釈可能な s3:// 形式のパスでメタデータを参照する。
- **Iceberg データ**：S3 互換ストレージの実データを対象エンジンが取得する。
- **既存メタデータの更新**：古い内部形式で記載された表では既存メタデータの更新が必要になる場合がある。

## 3. 処理の流れ

1. 外部エンジンからの要求に対してカタログが権限と保存場所を解決する。
2. 互換パスとアクセス情報を使い、メタデータとデータを参照する。
3. 既存の一部テーブルには別途メタデータの更新が必要になる。

記事では Horizon Catalog がストレージの内部識別を外部エンジンが解釈できる s3:// のパスへ解決する。古いメタデータでは一度だけメタデータ更新が必要な場合があり、記事のプレビュー期間中は Snowflake チームが依頼に応じて実行するとされる。実データをコピーする操作とは区別する。

## 4. 留意点

2026年10月の記事時点では private preview。対応ストレージや提供状況は利用前に確認する。既存表の更新はメタデータ層を対象とし、データファイルを移動するとは記載されていない。S3 互換ストレージを AWS S3 サービスと混同しない。

## 5. 実装例

S3 互換ストレージに置かれた Snowflake Horizon 管理 Iceberg テーブルを互換外部エンジンから利用する記事の構成例。記事時点ではプレビューであり、必要なエンドポイント・アクセス制御と利用条件を確認する。S3 互換ストレージの実際の提供元やネットワークは指定しない。

| 機能 | 担い手 |
| --- | --- |
| 外部エンジン | Spark / Trino 等の外部エンジン |
| カタログとアクセス判定 | Snowflake Horizon Catalog |
| ストレージ位置の解決 | Horizon のストレージ解決 |
| アクセスの許可 | カタログのアクセス制御 |
| Iceberg メタデータ | S3 互換の Iceberg メタデータ |
| Iceberg データ | S3 互換ストレージのデータ |
| 既存メタデータの更新 | 一度限りのメタデータ更新 |
