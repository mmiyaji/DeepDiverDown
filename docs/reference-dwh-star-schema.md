# DWH のスタースキーマとファクトの粒度

## 1. 粒度を宣言する

fact_order_line の1行は「1注文の1明細」。注文ヘッダ、明細、支払いでは粒度が異なる。売上例は注文の純額を円で持ち、明細の集計で注文の総売上を導く。税・返品の扱いは別途定義する。

## 2. ファクトとディメンション

ファクトは金額や数量と日付・顧客・商品のキーを持つ。ディメンションはラベルや分類を供給し、明細から対応する1行を引けるキーを持つ。注文明細に対する商品名の履歴が必要なら SCD の設計を確認する。

## 3. 集計の条件

同じ金額定義・通貨の明細は合計できる。注文数は明細数と違うので、注文IDを重複排除して数えるか、用途に合う別粒度のファクトを設ける。比率は集計後の分子・分母から再計算する。

## 4. 結合で崩れる例

一つの商品に複数の販促タグを直接結合すると、明細がタグ数だけ複製される。配賦のルールを決める、タグを集合として絞る、別の粒度で集計するといった対処を検討する。

## 図で確認するシナリオ

- **注文1件の売上と明細件数を集計** — 注文42に、1,200円と600円の明細を1行ずつ登録する。 → 日付・顧客・商品ディメンションの属性で絞る。 → 売上は1,800円、注文数は注文IDの重複を除いて1件になる。
- **タグ結合の多重計上を見つける** — 販促タグが2つある商品を確認する。 → 1,200円の明細をタグ2行と結合した場合、その明細が二重計上される。 → 対象タグを持つ商品の集合として明細を絞り、元の粒度で集計する。
