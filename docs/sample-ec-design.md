# ECサイト 注文基盤 基本設計書（サンプル）

> DeepDiverDown の動作確認用の架空の設計書。意図的にいくつか問題を含めている。

## 1. 概要
会員が商品を注文・決済し、確定メールを受け取るまでを扱う。

## 2. 外部接点
### 2.1 利用者
ブラウザ / スマホアプリから CDN 経由でアクセスする。
### 2.2 CDN
静的ファイルを配信し、API は ALB に転送する。
### 2.3 ALB
Web（BFF）に振り分ける。アイドルタイムアウト 30 秒。

## 3. アプリケーション
### 3.1 Web（BFF）
3 台構成。画面向けに API を集約する。注文サービスを同期呼び出しする。
### 3.2 注文サービス
2 台構成。注文を受け付け、在庫引当 → 決済 の順に同期で呼ぶ。確定後、注文イベントを Kafka に発行する。
### 3.3 在庫サービス
2 台構成。在庫を引き当てる。引当完了時に注文サービスへコールバックする。
在庫テーブルは注文 DB に同居させる（移行コスト削減のため）。
### 3.4 決済サービス
1 台構成（初期リリースは負荷が小さいため）。外部決済代行（PSP）を呼ぶ。タイムアウト 10 秒、リトライ 3 回。
### 3.5 通知ワーカー
1 台構成。Kafka の注文イベントを購読し、メール配信サービスに送る。

## 4. データ
### 4.1 注文 DB
RDS（Multi-AZ）。注文・在庫テーブル。
### 4.2 Kafka
3 ブローカー。トピック `order-events`。
### 4.3 Redis
セッション・カート。1 ノード。

### 5.1 決済代行（PSP）
### 5.2 メール配信

## 6. ユースケース
### 6.1 注文確定
利用者 → CDN → ALB → Web → 注文 → 在庫引当 → 決済 → PSP → 注文 DB 書込 → Kafka 発行 → 通知 → メール
### 6.2 カート参照
利用者 → CDN → ALB → Web → Redis
