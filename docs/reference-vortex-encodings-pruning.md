# Vortex：入れ子のエンコーディングと読み飛ばし

## 1. 題材と範囲

Vortex の 1 つのファイルで、読む範囲を絞る仕組みと、エンコードされた配列を扱う仕組みを追う。2026 年 11 月時点の公式ドキュメントに基づく。公式が示す性能数値はプロジェクトの自己申告であり、ここでは引用も検証もしない。図のデータや実行順は説明用で、実環境での計測は行っていない。

## 2. 条件の押し下げ

エンジンは Scan API にフィルタと必要な列を渡す。Scan API はフィルタとプロジェクションの押し下げに対応する（公式ページの記述）。条件はレイアウト木のルートから渡される。

## 3. ゾーンマップとセグメントの遅延取得

ZonedLayout は、フィルタによる読み飛ばし用にゾーンマップ（統計）を持つ。条件に合わない範囲は子レイアウトごと読まない。ゾーンの大きさと統計の種類は未確認。

レイアウトは、セグメントのバッファを必要になったときにセグメントソースから取得する。ローカルディスク、オブジェクトストレージ、リモートキャッシュなどのブロックストレージに対し、必要な範囲だけを読める。FlatLayout はシリアライズされた配列を 1 つ持つ。

## 4. 入れ子のエンコーディング

配列は FastLanes、FSST、ALP などの軽量エンコーディングで圧縮される。エンコーディングを選んで重ねる手順と組み合わせの規則は、取得した資料に記述がなく未確認。

## 5. 圧縮したままの演算

公式ページによると、多くの演算はデータを展開せずに実行できる。展開が必要な演算では、必要な範囲だけ展開した配列を作る。どの演算が展開なしで済むかの一覧は未確認。

## 6. シナリオの見方

「条件付きの読み取り」は、条件を渡し、ゾーンマップで範囲を絞り、残ったセグメントだけを取得して配列を復元し、圧縮したまま評価して結果を返す流れを順に選択して追う。展開が必要な場合の経路も含む。

## 7. 実装例：AWS の EC2 と S3

EC2 上の DataFusion または DuckDB が Vortex の統合を通じて S3 のオブジェクトを条件付きで読む構成例。複数の資料を組み合わせた代表例で、動作は未検証である。

| 機能配置 | AWS での担い手 |
| --- | --- |
| フィルタと列の指定 | EC2 上の DataFusion または DuckDB |
| レイアウト木・ゾーンマップ・評価 | EC2 上の Vortex ライブラリ（Scan 実装） |
| セグメントの取得元 | S3 上の .vortex オブジェクト |

AWS は EC2 と S3 の基盤を運用し、利用者はゲスト OS、ライブラリのバージョン、データと権限を管理する。
