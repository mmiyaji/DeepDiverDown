# モデルビューの試作

採用済みの試作（layout-flow・layout-layers・select-fast・flow-numbers・flow-trail・camera-auto）は既定で有効。`index.html?lab=名前` で試作を追加し、`?lab=-名前` で採用済みを外し、`?lab=off` で全部外す（タブの間は覚える）。2D の文字の下限（拡大率 0.78）は `?lab=zoom-floor-off` で外せる。

| 名前 | 内容 | 状態 |
| --- | --- | --- |
| `flow-numbers` / `flow-trail` / `flow-both` | シナリオ再生中、いまのステップの接続線の矢印の手前にステップ番号の丸（同じステップの接続は同じ番号、pointer-events:none）を出す。`flow-trail` は通過済みのステップの接続線を、細く淡い強調色（不透明度 0.65）で残す。`flow-both` は両方 | redshift-rms-distribution（3D）の 4 ステップで番号 3/2/3/1 個が出て、表示された番号とほかのラベルの重なりは 0（ステップ 1 だけ 3 個中 2 個。1 個は他ラベルと衝突して非表示）。snowflake「取り込みと BI を分離」step 1〜3 で通過済みの線が残ることを画像で確認。2D でも同様 | 番号はラベルの空きに合わせて縦にずれるか、衝突すると非表示になる。通過済みの線は細く、混んだ図では目立たない。複数の部品を束ねた図（機能配置）では最初の接続の状態だけが使われる |

| `layout-flow` / `layout-layers` | js/lab-layout.js。モデル読み込み直後（app.js の loadEntry の結果）に、表示用のコピーの座標だけを補正する。`layout-flow`：接続の向きから最長経路で段を決め（循環の戻り辺は無視）、同じ高さの枠を平均の段の順に左から並べ、枠内は段の順に x、同じ段は y を振り直す。無関係な部品の上を通る線が減るよう、同じ段の中で席を入れ替える。実装例の layout3d・layout2d と共通モデルの座標が対象。`layout-layers`：3D の実装例で、部品を役割ごとの床（上「制御・メタデータ」＝service/scheduler/catalog/policy・認証・カタログ、中「処理」＝worker/host/gateway・実行基盤、下「保存・データ」＝db/queue/cache/table/file）に分け、client/actor/external は左端の「利用者・外部」枠にまとめる。部品 6 個未満・役割が 1 つの図は変えない。併用可 | audit-layout-flow の飛び越し：全 566 図（実装例の 3D・2D）で 638 → 0（layers 単独は 3D のみ 0、2D は据え置きの 318）。比較用 5 図（3D・2D 合計）：snowflake 0→0、redshift-rms-distribution 0→0、fabric-onelake-shortcuts 0→0、snowflake-ingestion-cdc 24→0、microsoft-purview 18→0。補正の所要は 1 モデル最大 11 ms（Node）。弱点：循環・問い合わせの向きは DFS の戻り辺で決めるだけで、向きの意味は見ない。入口と出口を同じ枠に持つ枠は平均の段で右へ寄る（snowflake-ingestion-cdc の「外部」）。外部システム（データ源の DB など）も client/actor/external は一律に左端へ移る。layers は共通モデルのみの図（実装例なし）には効かない。同じ段の席が足りず飛び越しを避けられない場合の保証はない |
| `camera-auto` / `camera-keep` | js/scene3d.js のみ。`camera-auto`：3D の初期視点（fit('iso')、リセットも）を、方位角 8 × 仰角 3（24/38/55 度）の 24 候補から採点して選ぶ。部品中心を画面へ射影し、(a) 最小距離と 48px 未満の組の割合、(b) 部品の外接矩形が画面を占める割合、(c) 接続の向きが画面で左→右か（重み 0.4/0.25/0.35）。選んだ向きで全体を収める。回した後は従来どおり。`camera-keep`：2D⇄3D の切り替え・描き直しで、選択部品のページ上の位置（px）を保つ（はみ出すなら位置を軸に最大 0.5 倍まで縮小）。描画領域の大きさが落ち着く 4 秒間は 80ms ごとに保ち直す。どちらも window.__ddScene に scene を出す（計測用） | 部品中心の最小距離（px、scene.nodeScreen、同じ画面）：snowflake 53.5→79.4、redshift-rms-distribution 41.0→76.5（48px 未満の組 1→0）、fabric-onelake-shortcuts 55.4→81.7、snowflake-ingestion-cdc 75.5→105.4、microsoft-purview 112.8→124.4。選ばれた視点（方位角,仰角）：315,24 / 315,55 / 45,38 / 45,38 / 0,38。採点の合計は iso 0.777/0.747/0.772/0.863/0.854 → 0.877/0.862/0.904/0.965/0.860。camera-keep：redshift-rms-distribution で leader を選び 3D→2D→3D→2D→3D、選択部品の位置のずれは off で最大約 72px（449↔377）、keep で 9px（初回の落ち着き）以内 | 候補は部品中心だけを見るため、枠・接続線どうしの重なりや部品の大きさは見ない。仰角の候補が 3 つで、見下ろし過ぎ・低すぎの中間は試さない。採点の重みと 48px は目分量。iso ボタンも auto の向きになる。keep は選択が無い・画面外のときは何もしない。縮小で全体が小さくなる（最大 0.5 倍）。縮小・移動後は画面サイズが変わっても全体表示へ戻らない（回す・動かすと保持を解除）。ヘッドレスなど rAF が止まる環境でも動くよう setInterval を使う |
| `select-fast` / `perf-log` | js/scene3d.js・js/app.js・js/lab-perf.js。`perf-log`：描き直しの内訳を計り、`__ddPerf.run(12)` で部品を 12 個順に選んだときの中央値（ms）を返す。`select-fast`：部品・接続の選択、周辺のみ、接続の選択のように、部品の位置・床・枠・接続の経路が同じで見た目（不透明度・色・輪郭・太さ）だけが変わる更新は、シーンを作り直さず、変わった部品と接続だけ作り直して差し替え、既存の DOM ラベルは選択・輪郭・不透明度の属性だけ更新する（ghost・3 フレームの隠しも出さない）。表示切替・次元・テーマ・シナリオのステップ（パケット・番号が変わる）は従来どおり作り直す。ホバーは元から再描画なし | 5 図で選択 1 回あたり：drawScene 4.4〜5.0 → 3.4〜4.1 ms（部品・接続の生成 1.4〜2.0 → 0、差分更新 1.7〜2.3）、ラベルの配置 2.6〜3.5 → 0.9〜1.4 ms、選択から新しいラベルが落ち着くまで 67〜80 → 35〜39 ms（約 2 フレーム、従来は隠し 3 フレーム）。差分更新と全体再作成の比較：描画物 0 件差・ラベル属性 0 件差・配置 0 件差、画素差 0〜30 / 約 32 万（動くパケットのみ）。弱点：5 図はどれも 10 部品前後で、作り直し自体が 2 ms 台のため CPU の短縮は約 1 ms 止まり（効くのは待ち時間）。差分更新の部品は部品ごとに別の描画になり、描画の呼び出しが増える（大きい図で要確認）。ラベルが作り方で決まる部分まで同じでないと全体作り直しに戻る。2D の fit は差分更新では再実行しない |
