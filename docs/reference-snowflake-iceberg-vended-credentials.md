# Snowflake：Iceberg カタログの一時認証情報

## 1. 対象と前提

外部 Iceberg カタログから取得する短期認証情報とストレージへのアクセスを追う。 公式資料を組み合わせた説明用のモデルで、実機の配置や導入事例ではない。

## 2. 構成と役割

- **SQL を実行**：利用者が外部カタログの Iceberg テーブルを問い合わせる。
- **外部カタログ**：Iceberg REST カタログは表メタデータとスコープを絞った短期認証情報を提供する。
- **クエリの実行**：カタログを通じて対象テーブルを解決し、データを取得する。
- **表ごとの内部ボリューム**：カタログ発行の認証情報を用いるテーブル単位の内部ボリューム。表のライフサイクルに関連付く。
- **短期認証情報**：必要なスコープに限定された一時的なストレージ認証情報を取得し、期限に応じて更新する。
- **表のメタデータ**：Iceberg の metadata / manifest をたどりデータファイルを特定する。
- **データファイル**：認証情報を用いて Iceberg のデータファイルにアクセスする。

## 3. 処理の流れ

1. SQL に対し外部カタログから表の情報を取得する。
2. テーブル単位で短期認証情報を取得し、必要に応じ更新する。
3. Iceberg メタデータをたどって該当データを読む。

Snowflake の公開記事ではテーブルごとの hidden volume に認証情報管理を結び付け、短期資格情報を必要時に取得・更新する設計が示される。カタログへの認証と、カタログが発行するストレージ用資格情報は別であり、長時間クエリでは有効期限に対応する必要がある。

## 4. 留意点

認証情報の更新と有効期限、外部カタログ・クラウドストレージの対応は製品設定とバージョンに依存する。表ごとの内部ボリュームは利用者が通常直接管理する EXTERNAL VOLUME ではない。

## 5. 実装例

外部カタログの稼働場所は資料で特定できないため、図では利用者が運用する環境と仮定する（Polaris などの実装は未確認）。

外部 Iceberg REST カタログと顧客 S3 の Iceberg テーブルを Snowflake から読む概念例。カタログ側で一時認証情報の発行とアクセス権を設定し、対応する Snowflake の catalog integration を用意する。

| 機能 | 担い手 |
| --- | --- |
| SQL を実行 | 利用者の SQL |
| 外部カタログ | 外部 Iceberg REST カタログ |
| クエリの実行 | Snowflake のクエリエンジン |
| 表ごとの内部ボリューム | Snowflake の内部ボリューム |
| 短期認証情報 | vended credentials |
| 表のメタデータ | S3 の Iceberg メタデータ |
| データファイル | S3 の Iceberg データ |
