# 設計書 → モデル抽出プロンプト

以下を LLM（Claude 等）に渡し、出力を `models/<name>.model.js` として保存する。
**出力は必ず人がレビューする**（研究上、LLM はコンポーネント間の「関係」を誤りやすい）。

---

あなたはシステムアーキテクトです。次の設計書を読み、`docs/model-schema.md` の形式で
`window.MODEL = {...}` を出力してください。

ルール:
1. 設計書に書かれていない値は推測で埋めない。不明な項目は省略し、`unknowns` 配列に「何が不明か」を列挙する。
2. 各ノード・リンクに `src`（設計書の節番号）を必ず付ける。
3. 同期 / 非同期（`sync`）、台数（`replicas`）、タイムアウト（`timeoutMs`）、リトライ（`retry`）は本文の記述から読み取る。
4. ユースケースの節は `scenarios` に変換し、ステップごとに通るリンク ID を並べる。
5. 座標 `x,y` はフロア内で左→右に処理が流れるよう 0〜9 / 0〜3 の範囲で配置する。
6. 最後に「設計書内の矛盾・曖昧さ」を `review` 配列にまとめる。
